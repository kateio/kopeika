# План проекта: kopeika

## Цель проекта

Создать PWA-приложение для учёта личных финансов, которое выделяется среди конкурентов мультимодальным вводом транзакций (текст, голос, импорт файлов), умной автокатегоризацией и работой без привязки к банковским аккаунтам. Приложение работает offline-first на клиенте, не требует серверной инфраструктуры для базового функционала и устанавливается на телефон/десктоп как PWA без сторов.

## MVP scope (v1)

Минимальный продукт, который имеет смысл показать и которым можно реально пользоваться:

1. **Быстрый ручной ввод транзакций** — 2-3 тапа (сумма + категория). Это основной способ ввода, он должен быть быстрее всех конкурентов.
2. **Текстовый ввод в свободной форме** — «500₽ кофе», «обед 350», «такси 200₽ домой». Парсинг суммы, описания, попытка определить категорию по ключевым словам.
3. **Категории** — ~15-20 предустановленных (еда, транспорт, развлечения, одежда, здоровье, ЖКХ...) + CRUD для кастомных категорий.
4. **Автокатегоризация по правилам** — маппинг ключевых слов → категории («пятёрочка» → Продукты, «uber» → Транспорт). Обучение на корректировках пользователя.
5. **Круговая диаграмма расходов** — donut chart на главном экране с разбивкой по категориям. Фильтр по периоду (день/неделя/месяц/год).
6. **Импорт CSV** — универсальный импорт с маппингом колонок + 1-2 шаблона для популярных банков РФ.
7. **PWA с офлайн-режимом** — service worker, всё работает без интернета.
8. **Экспорт/импорт бэкапов** — JSON-файл для защиты от потери данных (критично для iOS, где IndexedDB может быть очищен).
9. **Базовая статистика** — итоги за период, топ категорий, средний расход в день.

**Что НЕ входит в MVP:** голосовой ввод, LLM-категоризация, бюджеты/лимиты, сканирование чеков, синхронизация, PDF-импорт, мультивалютность.

### Архитектура хранилища

**Вариант 1: Чистый клиент (IndexedDB)** — рекомендуется для MVP
- Все данные в IndexedDB через Dexie.js
- Бэкапы через экспорт/импорт JSON-файла
- Плюсы: нет backend, нет расходов на сервер, полная приватность
- Минусы: риск потери данных на iOS (7-дневный eviction), нет синка между устройствами
- **Важно:** обязательно реализовать автоматическое напоминание о бэкапе

**Вариант 2: Клиент + backend для синка** — для v3
- Данные хранятся локально (IndexedDB) + синхронизируются на сервер
- Backend: простой API на Node.js/Express или edge-функции (Cloudflare Workers / Vercel)
- БД: SQLite (Turso) или PostgreSQL
- Авторизация: email magic link или OAuth
- Плюсы: синхронизация, надёжное хранение, общие кошельки
- Минусы: расходы на инфраструктуру, сложность реализации

**Вариант 3: Клиент + LLM-API прокси** — для v2
- Минимальный backend только для проксирования запросов к LLM API (Claude/GPT)
- Нужен для автокатегоризации текстового/голосового ввода и транскрипции (Whisper)
- Может быть serverless-функцией (Cloudflare Worker, Vercel Edge Function)
- Плюсы: минимальная инфраструктура, LLM-фичи
- Минусы: стоимость API-вызовов, задержка

**Рекомендация:** Начать с Варианта 1 (MVP — чистый клиент). При добавлении LLM-фич — Вариант 3 (минимальный прокси). При добавлении синка — Вариант 2.

## Что требует решения от пользователя

Перед началом разработки нужны ответы на следующие вопросы:

1. **Одно устройство или несколько?** Если только одно — можно обойтись без backend надолго. Если синк нужен скоро — нужно закладывать архитектуру данных с учётом будущей синхронизации (CRDT, timestamp-based merge).

2. **Нужен ли облачный синк?** Если да — на каком этапе? Это определяет, нужен ли backend с самого начала или его можно добавить позже.

3. **Готова ли тратиться на LLM API для автокатегоризации?** Claude Haiku ($1/$5 за MTok) — ~$0.001 за транзакцию. При 30 транзакциях в день = ~$1/мес. Альтернатива — правила на клиенте (бесплатно, но менее точно).

4. **Какой банк основной?** Для приоритета формата CSV-импорта. Тинькофф и Сбер имеют разные форматы CSV.

5. **TailwindCSS или CSS Modules?** Стилевой подход — дело вкуса, но влияет на структуру проекта.

6. **Нужна ли монетизация?** Если планируется freemium — нужно определить, какие фичи будут платными. Если нет — проще архитектура.

7. **Один пользователь или семья?** Общие кошельки (как у Spendee) требуют backend + авторизацию. Если не нужно — значительно проще.

8. **Рублёвое приложение или мультивалютное?** Мультивалютность усложняет модель данных и UI. Для MVP рекомендуется одна валюта.

## Риски и неопределённости

### Высокий риск

- **Голосовой ввод на iOS PWA** — Web Speech API не работает в standalone mode. Единственное решение — backend с Whisper API, что добавляет инфраструктуру и стоимость. Альтернатива: голосовой ввод работает только в браузере (не из установленного PWA), но это плохой UX.

- **Потеря данных на iOS** — IndexedDB может быть очищен через 7 дней неиспользования. Для финансового приложения это катастрофа. Митигация: автоматические напоминания о бэкапе, возможно автоэкспорт через Web Share API.

### Средний риск

- **Парсинг PDF-выписок** — каждый банк имеет уникальный формат PDF. Парсинг ненадёжен, дорог (LLM) или требует специализированных библиотек (Tabula). Рекомендация: не делать в v1-v2.

- **Автокатегоризация без LLM** — правила по ключевым словам покрывают ~70-80% кейсов. Для оставшихся 20-30% нужны корректировки пользователя или LLM. Риск: пользователь разочаруется в «умности» приложения.

- **Объём парсеров банковских CSV** — в РФ нет стандартного формата, каждый банк — своя структура, кодировка (cp1251!), формат дат. Поддержка 5 банков = 5 парсеров с тестами и поддержкой изменений.

### Низкий риск

- **PWA-adoption** — пользователи не привыкли к PWA на телефоне. Нужен onboarding с инструкцией «Как установить». Но тренд растёт, iOS 26 улучшает поддержку.

- **Производительность с большим объёмом данных** — IndexedDB может тормозить при 10 000+ транзакций. Решается пагинацией и индексами в Dexie.js.

## Что НЕ делаем в v1

- Голосовой ввод
- Сканирование чеков / OCR
- LLM-автокатегоризация (только правила)
- Импорт PDF
- Синхронизация между устройствами
- Backend любого вида
- Общие кошельки / семейный бюджет
- Мультивалютность
- Бюджеты и лимиты (только трекинг)
- Повторяющиеся транзакции
- Push-уведомления
- Тёмная тема (можно добавить быстро, но не приоритет)
- Интеграция с банковскими API
- Мобильные виджеты
