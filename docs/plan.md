## Цель проекта

Создать iOS-first PWA для учёта личных финансов с мультимодальным вводом транзакций (текст, голос, импорт файлов), умной автокатегоризацией и мультивалютной поддержкой с v1. Приложение работает offline-first на клиенте (IndexedDB + Dexie.js), синхронизирует данные с облаком (Supabase Postgres) для надёжного хранения и multi-device доступа. Аутентификация через magic link с MVP. Не привязано к банковским API, устанавливается как PWA без сторов.

## MVP scope (v1)

Минимальный продукт, которым можно реально пользоваться:

1. **Аутентификация (magic link)** — вход по email через одноразовую ссылку. Supabase Auth из коробки. Без паролей.
2. **Backend на VM + Supabase** — Node + Fastify на VM (167.71.40.41), Supabase free tier для auth + Postgres DB. Cloud-хранение транзакций с синком.
3. **Быстрый ручной ввод транзакций** — 2-3 тапа (сумма + категория). Основной способ ввода, должен быть быстрее всех конкурентов.
4. **Текстовый ввод в свободной форме** — «500₽ кофе», «обед 350», «такси 200₽ домой». Парсинг суммы, описания, попытка определить категорию по ключевым словам.
5. **Категории** — ~15-20 предустановленных (еда, транспорт, развлечения, одежда, здоровье, ЖКХ...) + CRUD для кастомных категорий.
6. **Автокатегоризация по правилам** — маппинг ключевых слов → категории («пятёрочка» → Продукты, «uber» → Транспорт). Обучение на корректировках пользователя.
7. **Круговая диаграмма расходов** — donut chart на главном экране с разбивкой по категориям. Фильтр по периоду (день/неделя/месяц/год).
8. **Импорт CSV** — первый парсер под формат Т-Банка + универсальный импорт с маппингом колонок.
9. **PWA с офлайн-режимом** — service worker, всё работает без интернета. Оптимизация под iOS Safari. IndexedDB через Dexie.js как offline-кеш с синком в Supabase.
10. **Экспорт/импорт бэкапов** — JSON-файл для защиты от потери данных. Автоматический экспорт раз в N дней + ручной экспорт. Cloud-бэкап в Supabase.
11. **Базовая статистика** — итоги за период, топ категорий, средний расход в день.
12. **Мультивалютность** — поддержка нескольких валют с v1 (хранение суммы + кода валюты, конвертация по курсу для отчётов).
13. **Backend** — минимальный сервер для LLM-прокси (категоризация сложных кейсов), Whisper API прокси (голос), приём бэкапов.

**Что НЕ входит в MVP:** сканирование чеков/OCR, бюджеты/лимиты, PDF-импорт, общие кошельки, повторяющиеся транзакции.

### Дизайн-фаза (этап 4 — подробности)

Отдельный этап между каркасом и началом разработки UI. Цель — зафиксировать визуальный язык приложения до написания кода.

**Шаг 1. Анализ `Копейка.html`**
Изучить стартовый набросок: какие экраны нарисованы, какие компоненты (карточки, графики, ввод, навигация), стиль, цвета, типографика. Составить полный список экранов и компонентов с вариантами состояний (empty / loading / error / filled).

**Шаг 2. Перенос в Figma (делает пользователь)**
Пользователь создаёт Figma-файл с UI-kit и экранами. Оркестратор готовит структуру:
- Список компонентов и их варианты
- Типографические токены (размеры, веса — из Inter Tight)
- Цветовые токены (из `Копейка.html`: фон #ECE7DD и производные)
- Набор иконок для категорий
- Все состояния каждого экрана

**Что ожидается от пользователя на этом этапе:** создать Figma-файл, перенести туда компоненты из HTML-скетча, утвердить цветовую палитру, типографику, стиль иконок. Прислать ссылку на Figma-файл.

**Шаг 3. Живая страница компонентов в репо**
Альтернатива/дополнение к Figma — `/uikit` route в самом приложении (или Storybook), где видны все компоненты в одном месте. Пользователь может посмотреть в браузере (в том числе на iPhone) и попросить правки.

**Шаг 4. Итеративная разработка UI**
Пользователь хочет детально контролировать каждый экран. На этапе кодинга UI каждый экран ревьюится отдельно, до перехода к следующему. **Режим: один экран = один PR.**

### Архитектура

**Принцип: клиент работает offline-first, синхронизирует данные с облаком (Supabase).**

- **Клиент (PWA):** данные пишутся в IndexedDB через Dexie.js (мгновенный отклик) + синк с Supabase Postgres (cloud-хранение). Полная функциональность офлайн: ввод, просмотр, статистика, экспорт. При появлении сети — автосинк.
- **Auth:** Supabase Auth — magic link на email. Без паролей в MVP.
- **DB:** Supabase Postgres (free tier, 500 MB). Row-Level Security для изоляции данных пользователей.
- **Backend (VM 167.71.40.41):** четыре роли:
  1. **Whisper API прокси** — для голосового ввода (Web Speech API не работает в standalone PWA на iOS)
  2. **LLM прокси** — для категоризации сложных кейсов (экономный режим: только когда правила не справились)
  3. **Приёмник CSV-выписок** — опционально, если пользователь хочет загружать на сервер, а не парсить на клиенте
  4. **Бэкап-сервис** — JSON-экспорт как дополнительная страховка поверх cloud-синка

### Формат CSV Т-Банка

Первый CSV-парсер пишем под формат Т-Банка (основной банк пользователя). Формат выписки Т-Банка: CSV с разделителем `;`, кодировка может быть cp1251 или UTF-8. Типичные колонки: дата операции, дата платежа, номер карты, статус, сумма операции, валюта операции, сумма платежа, валюта платежа, кэшбэк, категория, MCC, описание. Точная структура уточняется по реальному файлу выписки пользователя.

## iOS-приоритет

Основной пользователь — iOS Safari. Каждый этап разработки проверяется в Safari на iPhone (реальное устройство или responsive mode).

### PWA на iOS

- Корректный `manifest.json`: `display: standalone`, `theme-color`, `background-color`
- `apple-touch-icon` (180×180), splash screens для всех размеров iPhone
- `meta viewport` с `viewport-fit=cover` для работы с safe-area
- Add to Home Screen — обязательная инструкция в README приложения и onboarding-экране

### Ограничения iOS Safari

- **Web Speech API** не работает в standalone PWA → голосовой ввод только через Whisper API на backend (запись MediaRecorder → отправка audio → возврат текста)
- **IndexedDB** может быть очищен через 7 дней неиспользования в standalone PWA → обязательны явные бэкапы: авто-экспорт раз в N дней + ручной экспорт + опциональный бэкап на сервер
- **Push-уведомления** поддерживаются с iOS 16.4, но требуют пользовательского разрешения

### UI-требования для мобильного

- Тач-таргеты ≥ 44pt (44×44 CSS px)
- `input type="number"` / `inputmode="decimal"` для вызова числовой клавиатуры
- Корректная работа с `safe-area-inset-*` (вырез, home indicator)
- `position: fixed` — проверять на iOS (известные баги с виртуальной клавиатурой)
- Тестировать с включённым Dynamic Type (доступность)

## Аутентификация и хранение данных

### Решение пользователя (зафиксировано 2026-05-12)

Backend + регистрация добавляются **с MVP**, не откладываются. Причины:
- IndexedDB на iOS чистится через 7 дней простоя — данные на устройстве уязвимы
- Хранение в облаке = резервная копия + multi-device sync с самого начала
- Дизайн логина / профиля заложить сразу, не переделывать UX потом

### Метод входа в MVP

**Magic link на email**:
- Пользователь вводит email
- На email приходит ссылка для входа (одноразовая, expire через 15-30 мин)
- Клик → залогинен в приложении
- НЕТ паролей, recovery, защиты от reuse — упрощает UX

Альтернативы (можно добавить позже):
- Apple Sign-In (1 клик на iOS) — для удобства
- Email + password — если магик не нравится

### Что нужно в дизайне

Экраны для добавления в Figma (когда пользователь будет крутить UI):
- **Login screen** — поле email + кнопка «Получить ссылку»
- **Check email screen** — «Проверь почту, мы прислали ссылку»
- **Logged-in confirm** — переход на главный после клика по ссылке
- **Profile / Account** — внутри Settings, новый пункт. Показывает email, кнопка «Выйти»
- **First-launch flow** — если данных нет, ведём на Login (вместо StartScreen с категориями)

После Login пользователь попадает на StartScreen (выбор категорий) для первой настройки.

### Хранение данных — этапированно

**Этап MVP (v1 с backend):**
- **Frontend:** PWA на сервере (VM 167.71.40.41)
- **Backend:** Node + Fastify на VM
- **Auth + DB:** Supabase free tier
  - 500 MB DB включено
  - Magic link auth из коробки
  - Postgres под капотом
  - Серверы Supabase в США/EU
- **Local cache:** Dexie.js + IndexedDB (offline-first, синк с Supabase)
- **Стоимость:** $0/мес на старте

**Этап production (если public release с РФ-юзерами):**
- Локализация по ФЗ-152: Postgres на серверах в РФ (Yandex Cloud / VK Cloud)
- Migration с Supabase
- Стоимость: $30-50/мес
- Отдельный roadmap-этап (v3, этап 25)

### Что хранится в backend (Supabase) — модель данных

```
users
  id, email, created_at, last_login

transactions
  id, user_id (FK), amount, currency, category_id, description, occurred_at, created_at

categories
  id, user_id (FK), name, emoji, color, type (expense|income)

settings
  user_id (FK), preferences (JSONB) — тема, валюты, бэкап-расписание
```

PDF-файлы (если решим хранить) — Supabase Storage, поле `pdf_url` в transactions.

### Что **не** хранится в backend

- Пароли в открытом виде (magic link их не использует)
- Anthropic API ключи (только env на backend)
- Sensitive логи (для PDF — только хэши для дедупликации, не контент)
- Анонимный трафик (никаких трекеров)

### Sync-стратегия

- Frontend пишет в **Dexie (IndexedDB)** сразу же → UI отвечает мгновенно
- Параллельно пишет в **Supabase** → cloud-копия
- При запуске приложения — pull последних изменений из Supabase в Dexie
- Конфликты разрешаются по `updated_at` (последняя запись побеждает)
- Offline-режим: работает без сети, при появлении сети — sync

### Privacy и безопасность

- HTTPS везде (Cloudflare / Let's Encrypt)
- Backend на нашей VM, frontend assets через CDN
- Supabase Row-Level Security: пользователь видит только свои транзакции
- (детальнее — в `docs/research/pdf-import.md` секция «Юридические аспекты»)

## Риски и неопределённости

### Высокий риск

- **Голосовой ввод на iOS PWA** — Web Speech API не работает в standalone mode. Решение: backend с Whisper API (есть VM). Стоимость Whisper API: ~$0.006/мин.

- **Потеря данных на iOS** — IndexedDB может быть очищен через 7 дней неиспользования. **Решено:** cloud-хранение в Supabase Postgres с MVP. IndexedDB теперь offline-кеш, а не единственное хранилище.

### Средний риск

- **Стоимость LLM API** — Claude Haiku ($1/$5 за MTok) — ~$0.001 за транзакцию. При 30 транзакциях в день = ~$1/мес. Митигация: LLM только как fallback, когда правила не справились (экономный режим).

- **Парсинг PDF-выписок** — каждый банк имеет уникальный формат PDF. Рекомендация: не делать в v1-v2.

- **Автокатегоризация без LLM** — правила по ключевым словам покрывают ~70-80% кейсов. Для оставшихся 20-30% — LLM через backend (решение принято).

- **Объём парсеров банковских CSV** — в РФ нет стандартного формата, каждый банк — своя структура, кодировка, формат дат. В v1 только Т-Банк, остальные в v2.

### Низкий риск

- **PWA-adoption** — пользователи не привыкли к PWA на телефоне. Нужен onboarding с инструкцией «Как установить». iOS 26 улучшает поддержку PWA.

- **Производительность с большим объёмом данных** — IndexedDB может тормозить при 10 000+ транзакций. Решается пагинацией и индексами в Dexie.js.

## Что НЕ делаем в v1

- Общие кошельки / семейный бюджет
- Бюджеты и лимиты (только трекинг)

- Push-уведомления
- Тёмная тема (можно добавить быстро, но не приоритет)
