# Анализ конкурентов: приложения учёта личных финансов

## Цель исследования

Анализ рынка приложений для учёта личных финансов перед разработкой **kopeika** — PWA-приложения с импортом банковских выписок, текстовым и голосовым вводом транзакций, автокатегоризацией и визуализацией расходов.

Исследовано **11 приложений** (4 RU/CIS + 7 глобальных), включая одно с сильным голосовым AI-вводом (Finly).

### Обозначения
- **да** — фича полноценно реализована
- **нет** — фича отсутствует
- **частично** — есть с ограничениями
- **(обуч.)** — обучается на корректировках пользователя
- **(платно)** — доступно только в платной версии

## UX-паттерны, встречающиеся у большинства

1. **Быстрый ввод транзакции** — все приложения стремятся к минимуму тапов (Monefy — 2 тапа, CoinKeeper — drag-and-drop, Toshl — 4 тапа). Это критический KPI для retention.

2. **Круговая диаграмма (pie/donut chart) на главном экране** — присутствует в 9 из 11 приложений. Это де-факто стандарт визуализации расходов по категориям.

3. **Freemium-модель** — 10 из 11 приложений (кроме YNAB) используют freemium. Бесплатная версия для привлечения, платная — для продвинутых фич.

4. **Предустановленные категории + кастомные** — большинство предлагает 12-20 базовых категорий с возможностью создания своих (в платной версии).

5. **Мультивалютность** — поддерживается почти всеми (50-200 валют).

6. **Повторяющиеся транзакции** — есть у большинства (подписки, зарплата, аренда).

7. **Теги/метки как альтернатива подкатегориям** — Toshl, Spendee, Wallet используют теги вместо жёсткой иерархии подкатегорий. Более гибкий подход.

8. **Синхронизация между устройствами** — cloud sync есть у всех, кроме Monefy (Dropbox/Google Drive) и kopeika-типа приложений.

9. **Экспорт в CSV/Excel** — есть практически у всех, часто в платной версии.

10. **Сканирование чеков** — растущий тренд (Finly, Spendee, Дзен-мани через QR-код ФНС, Money Lover).

## Сложные места и альтернативы

### Голосовой ввод

**Текущая ситуация:** из 11 исследованных приложений полноценный голосовой ввод есть только у **2** — CoinKeeper (платно) и Finly. Большинство не реализуют голосовой ввод вообще.

**Технические варианты для PWA:**

| Подход | Плюсы | Минусы | Сложность |
|---|---|---|---|
| **Web Speech API** | Бесплатно, встроено в браузер, работает на Chrome/Android | **Не работает в standalone PWA на iOS Safari**. Баги в Safari. | S (реализация), но ограничения критичны |
| **OpenAI Whisper API** | Высокое качество, мультиязычность, $0.006/мин | Требует backend-прокси. Latency. Стоимость при масштабе. | M |
| **Whisper.js (WASM в браузере)** | Оффлайн, бесплатно, приватность | Медленно, большой download модели (~40-150 МБ), низкая точность vs API | L |
| **Нативный микрофон + серверная транскрипция** | Работает везде, высокое качество | Нужен backend, задержка, стоимость | M |

**Критическое ограничение iOS:** Speech Recognition API работает в Safari на iOS, но **не работает в установленном PWA (standalone mode)**. Это значит, что голосовой ввод через Web Speech API **не будет работать на iPhone после установки на домашний экран**. Это подтверждено на [whatpwacando.today](https://whatpwacando.today/speech-recognition/) и [caniuse.com](https://caniuse.com/speech-recognition).

**Рекомендация:** Для MVP — Web Speech API (покрывает Android и десктоп). Для полноценной iOS-поддержки — Whisper API через backend. Реализацию голосового ввода стоит отложить до v2.

### Автокатегоризация

**Что используют конкуренты:**
- **Простые правила по payee/мерчанту** — YNAB, Тинькофф (MCC-коды)
- **ML с обучением на корректировках** — Wallet, Дзен-мани, Toshl, Spendee
- **LLM для natural-language ввода** — CoinKeeper (AI-ассистент), Money Lover (Assistant), Finly

**Альтернативы для kopeika:**

| Подход | Точность | Стоимость | Сложность |
|---|---|---|---|
| **Правила по ключевым словам** — маппинг «Пятёрочка» → Продукты, «Uber» → Транспорт | ~70-80% | Бесплатно | S |
| **LLM API (Claude/GPT)** — отправка описания транзакции в LLM | ~90-95% | $0.001-0.01/транзакция | M (нужен backend) |
| **Гибрид: правила + обучение на корректировках** — как Дзен-мани | ~85-90% (со временем) | Бесплатно | M |
| **Локальный ML (TensorFlow.js)** — классификация в браузере | ~80-85% | Бесплатно | L |

**Рекомендация:** Для MVP — правила по ключевым словам + обучение на корректировках пользователя (всё на клиенте). Для v2 — LLM API для текстового/голосового ввода (требует backend-прокси). Это покрывает 85%+ кейсов и не требует затрат.

### Парсинг банковских выписок

**Доступные форматы в РФ:**
- **CSV** — Тинькофф, Сбербанк, Альфа-Банк, ВТБ (кодировка cp1251, разные структуры колонок)
- **PDF** — все банки (но парсинг сложный)
- **OFX** — ограниченно (через сторонние инструменты вроде [ofxstatement-russian](https://github.com/gerasiov/ofxstatement-russian))
- **Excel/XLSX** — Сбербанк, Альфа-Банк

**Проблемы парсинга PDF:**
- Нет стандартизированного формата
- Каждый банк — своя верстка
- Варианты парсинга: Tabula (Java), pdf.js + ручной парсинг, LLM-парсинг (дорого), ABBYY FineReader (коммерческий)
- PDF-парсинг — головная боль, это подтверждают все конкуренты (никто не поддерживает PDF-импорт кроме как через банковские API)

**Сколько форматов поддерживать:**
- **РФ:** 4-5 банков (Тинькофф, Сбер, Альфа, ВТБ, Райффайзен) × CSV = 4-5 парсеров
- **Глобально:** стандартизированные OFX/QFX/QIF покрывают большинство банков

**Рекомендация:** Для MVP — универсальный CSV-импорт с маппингом колонок (как у Toshl) + 2-3 готовых шаблона для популярных банков РФ. PDF-импорт — отложить до v3 или не делать вовсе.

### PWA-ограничения

**Критические ограничения iOS Safari для PWA:**

| Возможность | iOS PWA | Android PWA | Десктоп |
|---|---|---|---|
| **IndexedDB** | до 50 МБ, eviction через 7 дней | сотни МБ, стабильно | сотни МБ |
| **Push-уведомления** | iOS 16.4+ (только с домашнего экрана) | да | да |
| **Фоновая синхронизация** | **нет** | да | да |
| **File System Access API** | **нет** | нет | да (Chrome) |
| **File input (чтение)** | да | да | да |
| **Камера/микрофон** | частично (перезапрос каждую сессию) | да | да |
| **Speech Recognition** | **нет в standalone PWA** | да | да (Chrome) |
| **Service Worker** | да (с ограничениями кеша) | да | да |
| **Web Share API** | да | да | да |

**Ключевые риски для kopeika:**
1. **Потеря данных на iOS** — IndexedDB может быть очищен при неиспользовании 7 дней. Критично для финансового приложения. Решение: экспорт/импорт бэкапов, или backend-синхронизация.
2. **Голосовой ввод на iOS** — не работает в standalone PWA. Решение: Whisper API через backend.
3. **Нет фоновой синхронизации на iOS** — нельзя синхронизировать данные в фоне. Только при открытии приложения.

**Рекомендация:** Проектировать с учётом worst-case (iOS). Обязательно реализовать экспорт/импорт бэкапов. Для критичных данных — предупреждение пользователю о регулярном использовании приложения.

## Рекомендации по MVP

### v1 (MVP) — базовый трекер с умным вводом
- Ручной ввод транзакций (быстрый, 2-3 тапа)
- Предустановленные категории (~15-20) + создание кастомных
- Текстовый ввод в свободной форме («500р кофе»)
- Круговая диаграмма расходов по категориям
- Импорт CSV (универсальный маппинг колонок)
- Автокатегоризация по правилам (ключевые слова)
- PWA с офлайн-режимом (IndexedDB)
- Экспорт/импорт бэкапов (JSON)

### v2 — автоматизация и аналитика
- Голосовой ввод (Web Speech API + Whisper API fallback)
- LLM-автокатегоризация для текстового/голосового ввода
- Готовые шаблоны для CSV банков РФ (Тинькофф, Сбер, Альфа)
- Бюджеты и лимиты по категориям с визуальным прогрессом
- Тренды и сравнение периодов
- Повторяющиеся транзакции (подписки)
- Теги/метки

### v3 — продвинутые фичи
- Сканирование чеков (OCR)
- Cloud-синхронизация между устройствами
- Общие кошельки (семья/пары)
- «Финздоровье» — индекс финансового здоровья
- Мониторинг подписок
- Импорт PDF-выписок (если целесообразно)
- Мультивалютность
